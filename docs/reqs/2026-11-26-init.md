# 작업 상세 내용
실행 시 `$HOME/.kuri/settings.yaml`의 kubeconfig 경로와 선택된 context를 사용합니다. 기본 kubeconfig는 `$HOME/.kube/config`입니다. 앱 초기 실행 때 설정 파일이 없으면 기본값을 저장합니다.

1. 설정된 IPv4/IPv6 루프백 포트에서 reverse proxy를 엽니다. 기본값은 80입니다. 직접 바인딩 권한이 부족하면 launchd 소켓 등록을 사용합니다.
    - macOS의 localhost:80 권한과 launchd 방식을 추가하고, 수정한 계획을 다시 검토해 주세요.
        - 127.0.0.1:80과 [::1]:80을 kuri가 직접 열려면 관리자 권한이 필요합니다. go run .으로 직접 실행할 때도 이 제한이 적용됩니다.
        - kuri가 일반 사용자로 실행하는 방식은 시스템 LaunchDaemon에 루프백 80 포트를 Sockets로 등록하고 UserName에 실행하는 사용자 계정을 지정하는 것입니다. 등록 단계에는 관리자 권한이 필요합니다. kfurl에는 launch_activate_socket()으로 열린 소켓을 받아 Go HTTP 서버에 넘기는 코드가 필요합니다.
        - 사용자는 macOS의 로그인 항목 화면에서 앱 자동 실행을 설정합니다. 앱은 로그인 시 또는 직접 열 때 저장된 프록시 자동 시작 옵션을 따릅니다. 자동 시작을 꺼도 이미 가동 중인 프록시는 계속 실행하며, 명시적 Start도 사용할 수 있습니다.
        - 별도로 `kuri install`을 실행하면 프록시의 부팅 등록이 적용됩니다. 이 경우에도 자동 시작 옵션이 켜진 경우에만 부팅이나 HTTP 요청으로 시작합니다. `Stop`과 `Quit`는 포트포워딩과 프록시를 종료하며, launchd 수신 포트 예약을 유지합니다. 같은 부팅에서 HTTP 요청만으로 프록시가 재개되지 않습니다.
        - 참고 자료는 [Apple LaunchDaemon](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html) 문서입니다.
2. 서버는 설정에 켜진 URI 호스트 형식만 처리합니다. 아래 예시는 기본 서비스 도메인 `kuri.localhost`를 사용합니다. Context가 꺼져 있으면 해당 context의 요청을 거부합니다.
    - type A: `{service}.{namespace}.{ctx}.kuri.localhost`: 가장 일반적인 방법. service에 정의된 포트가 하나라면 해당 포트로 연결. 하나의 서비스 리소스에 item이 여러개라면 `http` 이름을 가진 포트로 연결. item이 여러개고 http 이름도 없다면 연결하지 않음
    - type B는 `{portName}.{service}.{namespace}.{ctx}.kuri.localhost` 형식을 사용합니다. `portName`과 `spec.ports[].name`이 같은 TCP 항목을 선택하고 해당 항목의 `targetPort`로 Pod에 연결합니다. Headless Service(`clusterIP: None`)이거나 `targetPort`를 생략한 경우 Service의 `port`를 사용합니다. 이름이 일치하는 TCP 항목이 없으면 연결을 거부합니다.
    - type C: `{service}.{namespace}.kuri.localhost`: 현재 context로 ctx를 선택
3. 요청이 들어오면 연결된 포트포워딩 리스트에서 찾거나 k8s service에 새로운 포트포워딩을 열고 reverse proxy를 연결.
    - 기본 Keep-Alive는 마지막 요청부터 60분입니다. 연결을 연 시점을 기준으로 설정하거나 Keep-Alive를 꺼서 요청마다 포워드를 열고 응답이 끝나면 닫을 수 있습니다.
    - 연결되어있는 포트포워딩은 10초 주기로 요청을 보내서 연결이 끊기지 않았는지 확인, 끊겼다면 남은 timer 동안 연결 상태를 유지해야하므로 다시 포트포워딩을 열어야 함
    - 포워드 포트 범위는 양쪽 경계를 포함합니다. 기본값은 30000부터 39999까지입니다. 재사용 가능한 포트가 없으면 가장 오래 연결된 Keep-Alive 포워드를 종료해 포트를 할당합니다.

## 설정 적용

- Settings에서 저장하면 실행 중인 서버가 설정을 반영합니다. 수신 포트가 바뀌면 프록시를 자동으로 재시작합니다.
- 포트 변경이 실패하면 YAML의 `server.port`를 이전 값으로 복원합니다. 설정 창의 입력값을 보존하고 `Save Server Settings` 바로 위에 영문 오류를 표시합니다.
- 메뉴의 `Recent Services`에는 이번 서버 실행에서 연결한 서비스를 최신순으로 최대 10개 표시합니다.


# 로깅

실행 중 사용자가 이 reverse proxy 서버에 요청을 보낼 때 마다 언제, 어떤 domain으로 요청을 했고, 서비스 연결에 성공했는지 여부, (성공했다면) 어떤 서비스인지 (config id, alias, context, local_addr, local_port, namespace, protocol, remote_port, service), (실패했다면) 왜 실패했는지를 json structured log 형식으로 저장해야 함.
로그는 `$HOME/.kuri/access.log` 파일에 저장하고 최근 72시간이내 그리고 최대 파일 용량 100MiB로 제한. 72시간을 넘거나 100MiB를 넘는 경우 해당 log line을 삭제. 이 기준은 비동기로 평가하지 말고 마지막 로그를 파일에 추가하기 전에 평가해서 업데이트해야 함. 따라서 로그가 오랫동안 업데이트가 안되는 경우 72시간을 넘는 로그가 존재 할 수도 있음
access.log에는 서비스가 시작한 시점, stop 명령으로 종료된 시점에도 적절한 로그를 남겨야 하고 기존 로그 아래에 추가해야 함.
로그, help message 등은 모두 영어로 작성.


# 실행 방법

build 된 바이너리 외에도 `go run .`을 통해 실행 할 수 있어야 함.

- `go run .`은 프로그램을 foreground에서 실행. 현재 실행중 로그가 console 화면에 표시되어서 사용자에게 보여야 함. 로그 내용은 console과 함께 파일로도 fanout 되어야 함.
- `go run . help`는 실행 가능한 명령과 그 명령에 대한 help message를 모두 표시 후 종료해야 함.
- `go run . start`는 background로 실행되어야 함. console app은 background로 실행해도 터미널 창이 남기 때문에 gui app으로 작성하는 것으로 고려해야 함. background로 실행 직후 실행된 프로세스의 pid를 포함한 로그를 남겨야 함.
- `go run . stop`은 background로 실행중인 프로그램을 종료. 만약 실행중인 프로그램이 없다면 console에 에러 메시지를 표시하고 exit=1. 이 메시지는 로그가 아닌 단순 stdout. 정상적으로 종료되었다면 종료한 pid를 출력하고 종료.
- `go run . status`는 현재 프로그램의 실행 상태를 출력. 이 내용은 로그로 남기지 않고 stdout으로만 출력되어야 함. 다음 정보를 출력:
    - 실행 요약
        - 현재 실행 상태
        - 실행중이라면 pid, 시작시간, 현재 연결되어있는 서비스 수
    - 연결된 서비스 목록 (실행중일때만 제공)
        - 다음 항목들을 go [bubbletea](https://github.com/charmbracelet/bubbletea)를 사용해서 inline [table layout](https://github.com/charmbracelet/bubbletea/tree/main/examples#table)으로 표시되어야 함.
            - context (화면에는 `ctx`라고 표시): k8s context name
            - namespac4e
            - service: k8s service name
            - remote port: 포트포워딩으로 연결된 k8s service port. service item에 name이 지정되어있는 경우 다음 format으로 출력되어야 함: `{portNumber} ({serviceItemName})`
            - local port: 포트포워딩으로 연결된 local port
            - connected: 포트포워딩 연결을 유지하고 있는 시간. `{n}s ago`, `{n}m ago`, `{n}h ago`, `{n}d ago` 중 하나의 형태를 사용. 나누어 떨어지지 않는 경우 --예를 들어 185초는 3분보다 크고 4분보다 작음--에는 반올림한 값을 사용
                - `{n}s ago`: [0, 120)s 까지
                - `{n}m ago`: [2, 60)m 까지
                - `{n}h ago`: [1, 24)h 까지
                - 이후는 `{n}d ago`로 표시
