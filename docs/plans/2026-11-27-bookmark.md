# Bookmark 실행 계획

Settings에서 Kubernetes Service를 북마크에 추가하고 순서를 정합니다. 포트포워딩 기록이 없거나 프록시가 중지된 상태에서도 메뉴 막대에서 북마크를 검색하고 복사합니다. 목표 버전은 `1.3.0`입니다. 이번 검증용 빌드에는 기존 규칙에 따라 `v1.3.0-rc{yyyymmddhhmm}`을 사용합니다. [요구사항](../reqs/2026-11-27-bookmark.md)

## 현재 동작

- `cmd/kuri-launcher/settings_darwin.m`의 `build`와 `toolbarAllowedItemIdentifiers:`에 `General`, `Network`, `About`이 정의돼 있습니다. `createDialog:size:`와 `dialogActions:action:in:`은 별도 자식 창과 버튼을 배치합니다.
- `cmd/kuri-launcher/popover_darwin.m`의 `showRecent:`, `layoutRecent`, `handleKey:`와 `copyForward:`가 보조 패널, 화면 가장자리 배치, 키 탐색, URL 복사와 1초 피드백을 처리합니다. Recent Services는 `__menu_state`의 데몬 조회 결과에 의존합니다. [메뉴 상태 조회](../../internal/daemon/menu_state.go)
- `internal/forward/kubernetes.go`의 `LoadKubernetes`, `ContextNames`, `client`는 설정에 지정된 kubeconfig에서 컨텍스트를 읽고 인증을 적용합니다. `internal/route/service.go`의 `ChooseServicePort`는 TCP 포트만 선택하며, 포트 이름이 비어 있으면 단일 포트나 이름이 `http`인 포트를 선택합니다.
- `internal/route/host.go`의 `Parse`는 도메인 형식과 활성 컨텍스트를 검사합니다. `ForwardAddress`는 Recent Services에 사용하며 기본 포트인 경우 짧은 주소를 선택할 수도 있습니다. Bookmark는 요구사항에 따라 컨텍스트가 명시된 주소를 사용합니다.
- `internal/settings/store.go`는 `KnownFields(true)`로 설정 YAML을 읽습니다. 새 YAML 키를 추가하면 이전 CLI나 등록된 데몬이 설정을 읽지 못할 수 있습니다. [설정 저장 코드](../../internal/settings/store.go)
- `deploy/macos/VERSION`은 `v1.3.0`이고 `build-version.sh`는 개발 빌드에 UTC 분 단위 접미사를 붙입니다. 현재 체크아웃에서 스크립트 출력 `v1.3.0-rc202611270806`을 확인했습니다. `build-app.sh`는 `KuriVersion`에 전체 버전, `CFBundleShortVersionString`에 `1.3.0`을 기록합니다. [버전 규칙](../../deploy/macos/build-version.sh)

## 1. 저장, Kubernetes 조회, 주소 계산

- `internal/settings/bookmarks.go`에 로컬 목록을 추가합니다. `~/.kuri/bookmarks.yaml`에 추가 순서대로 `id`, `name`, `kubeconfig_path`, `context`, `namespace`, `service`, `port_name`을 저장합니다. `name`과 `port_name`은 비워 둘 수 있습니다. 파일이 없으면 빈 목록을 반환합니다. `store.go`의 파일 소유권, 심볼릭 링크와 용량 검사, 잠금 및 임시 파일 교체를 재사용합니다. 목록 읽기 오류는 UI에서 안내하며 파일을 보존합니다.
- Add는 저장 목록 전체에서 `(context, namespace, service, port_name)`이 같은 항목을 찾습니다. 실제 컨텍스트 이름과 저장할 Port Name을 비교합니다. 빈 Port Name은 기본 포트 선택을 뜻하며, 명시한 포트 이름과 별도로 비교합니다. `Name`은 중복을 허용합니다. kubeconfig 경로가 달라도 네 값이 모두 같으면 기존 항목, 이름, 순서와 파일을 그대로 두고 변경 없음으로 응답합니다. 새 항목에만 고유 ID를 부여해 맨 뒤에 추가합니다. 같은 추가 요청을 재시도해도 같은 규칙을 적용합니다.
- `-`는 선택한 ID를 삭제합니다. 순서 변경은 드래그를 시작할 때 본 ID 순서와 저장된 순서가 일치할 때만 전체 순서를 교체합니다. 충돌하면 최신 목록을 다시 표시합니다. 변경을 저장하면 결과를 화면에 반영합니다. 북마크는 Settings의 Reset 및 네트워크 설정 전송과 별개로 보관합니다. `internal/settings/transfer.go`의 `ExportTransfer`에 북마크 파일의 직접 경로와 같은 파일을 가리키는 경로를 보호 대상으로 추가합니다.
- `internal/forward/bookmarks.go`에서 기존 Kubernetes 클라이언트로 선택된 컨텍스트의 Namespace를 조회하고, 선택된 Namespace의 Service를 조회합니다. Service 선택 시 `spec.ports`를 읽어 이름이 있는 TCP 포트를 선택지로 반환합니다. 컨텍스트 목록은 kubeconfig에서 로컬로 읽습니다. Kubernetes 조회는 해당 단계의 목록 또는 Service 메타데이터 읽기로 한정하고, 페이지네이션과 요청 시간 제한을 적용합니다. RBAC, 인증, 시간 초과 오류는 해당 선택 상자에 표시합니다. 빈 검색어나 입력 변경은 이미 불러온 목록에만 적용합니다.
- `main.go`에서 런처 전용 `__bookmarks`를 연결하고 `settings_bookmarks.go`에서 목록, 선택지, 추가, 삭제, 순서 변경 및 메뉴 응답을 처리합니다. Add는 기존 항목을 먼저 검사합니다. 일치하는 항목이 있으면 kubeconfig와 Kubernetes API를 조회하기 전에 종료합니다. 새 대상은 활성 kubeconfig 경로와 내용이 선택지를 불러올 때와 같은지 확인하고 Service를 다시 읽어 `ChooseServicePort`로 검증합니다. Kubernetes 요청은 잠금 밖에서 수행합니다. 저장 직전에 잠금 안에서 대상의 중복 여부를 다시 확인해 동시 제출도 하나만 추가합니다. 추가할 때는 저장된 설정과 kubeconfig가 검증 시점과 일치하는지 확인합니다. kubeconfig가 바뀌었다면 Name 초안을 보존하고 현재 컨텍스트부터 다시 선택하도록 안내합니다.
- 포트 이름이 비어 있으면 TCP 단일 포트나 TCP `http`로 해석되는 경우에 추가합니다. 포트가 여러 개이고 기본 포트를 고를 수 없으면 `This service has multiple ports. Select a Port Name.`을 표시합니다. 포트가 없거나 TCP 포트를 지정할 수 없으면 해당 원인을 표시합니다. 이름을 명시하면 해당 TCP 포트만 허용합니다. 기본 선택은 빈 값 그대로 저장합니다.
- `internal/route/host.go`에 Bookmark용 명시 주소 생성을 추가합니다. 활성 설정의 도메인, 프록시 수신 포트, 사용자 지정 컨텍스트 별칭 또는 기존 DNS용 기본 별칭을 사용합니다. 포트 이름이 있으면 선택한 이름을 항상 앞에 붙이고, 없으면 `service.namespace.ctx` 형식을 사용합니다. 수신 포트가 80인 경우 접미 포트를 생략합니다. `Parse`로 역검증해 저장한 컨텍스트와 선택자가 일치할 때만 URL을 반환합니다.
- 북마크는 추가한 kubeconfig 경로와 실제 컨텍스트 이름에 연결합니다. 다른 kubeconfig를 활성화해도 항목과 순서는 남으며 해당 항목에 복사할 수 없는 이유를 표시합니다. 같은 경로에서 같은 이름의 컨텍스트가 다른 클러스터를 가리키면 그 파일의 최신 정의를 따릅니다. 제거된 컨텍스트, 제외된 컨텍스트, 충돌한 별칭, 꺼진 도메인 형식에도 복사할 수 없는 이유를 표시합니다. 메뉴는 저장된 설정과 로컬 kubeconfig만 읽습니다. 프록시가 설정을 적용하기 전에는 복사한 주소와 수신 설정이 다를 수 있습니다. Service 삭제나 포트 변경은 URL 접속 시 프록시의 기존 라우팅 처리에서 드러납니다.

## 2. Settings의 Bookmark 탭

- `cmd/kuri-launcher/settings_darwin.m`에서 탭 순서를 `General`, `Bookmark`, `Network`, `About`으로 지정합니다. 빈 목록에도 `Bookmark` 제목과 설명을 표시합니다. 설명은 `Open services from the menu bar, even when no port forward is active.`를 사용합니다. Reset 확인 창에는 북마크를 보존한다고 표시합니다.
- `cmd/kuri-launcher/bookmarks_darwin.m`에서 `NSTableView`와 스크롤 영역을 구성합니다. 헤더는 스크롤에 고정하고 `Name`, `Context`, `Namespace`, `Service`, `Port Name` 순으로 표시합니다. 본문은 교대로 줄 배경색을 적용해 8행 높이를 유지합니다. 빈 자리에도 줄무늬를 채우며 선택하거나 드래그할 수 있는 대상은 저장된 항목입니다. 9번째부터 본문을 세로로 스크롤합니다. 하단 `+`로 추가 창을 열고 행 하나를 선택하면 `-`를 활성화합니다. 드래그 중 행 ID와 삽입 위치를 사용해 순서를 계산합니다.
- `Add Bookmark Item`은 기존 자식 창과 버튼 배치 방식을 사용합니다. `Name`은 자유 입력으로 두고 `Name`과 `Port Name` 옆의 `(optional)`에 보조 색상을 적용합니다. `Context`, `Namespace`, `Service`, `Port Name`을 열면 키보드로 검색할 수 있습니다. 대소문자를 구분하지 않는 부분 문자열로 필터링하고 키보드로 옵션을 선택합니다. 상위 선택을 바꾸면 하위 선택과 목록을 비웁니다. 현재 선택의 응답만 적용하고, 대기 중이거나 선행 선택이 빠진 하위 상자는 비활성화합니다. `Port Name`은 빈 값으로 되돌릴 수 있습니다.
- `Context`, `Namespace`, `Service`를 골라야 `Add item`을 활성화하며 Go 핸들러에서 세 값을 다시 검사합니다. 새 대상에서 Port Name을 생략할 수 있는지는 클릭한 뒤 검증합니다. `Cancel`은 조회 중에도 초안을 버릴 수 있습니다. 제출 중에는 중복 클릭, `Cancel`, 닫기를 잠그고 결과를 기다립니다. 새 항목을 저장하면 목록 맨 아래에 표시하고 창을 닫습니다. 이미 저장된 대상이면 목록, 입력과 창을 유지하고 별도 안내나 메뉴 갱신 없이 제출을 끝냅니다. 검증 또는 저장 오류가 나면 입력과 창을 유지하고 원인을 표시합니다. `bookmarks_darwin.go`와 헤더에서 기존 `commandRunner.runInput`으로 오프 메인 스레드에서 실행하고, 창과 요청마다 응답을 식별해 늦은 응답이 새 창에 반영되지 않게 합니다. 기존 Settings의 미저장 입력과 이 창의 상태를 독립적으로 유지합니다.

## 3. 메뉴 막대에서 검색과 복사

- `cmd/kuri-launcher/popover_darwin.m`에서 `Recent Services` 바로 위에 `Bookmarked Services`를 배치합니다. 두 항목 사이에 구분선은 없습니다. 포인터가 행에 올라가면 강조하고 화면의 여유에 따라 오른쪽 또는 왼쪽으로 보조 패널을 엽니다. 두 보조 패널은 한 번에 하나를 표시합니다. 기존 배치, 강조, 닫기 동작을 재사용하고 검색 필드에 입력하는 동안 포인터가 벗어나도 입력 포커스를 유지합니다.
- 보조 패널을 열 때 `__bookmarks` 메뉴 응답을 한 번 요청합니다. 이미 열린 패널은 Settings에서 추가, 삭제, 순서 변경이나 주소에 영향을 주는 설정 저장이 성공하면 갱신합니다. `__menu_state`의 주기적 조회, 프록시 PID, 활성 포트포워딩과 별개인 경로입니다.
- 패널 상단에 `Search...` 입력과 구분선을 둡니다. Name, Context, Namespace, Service, Port Name 중 하나에 검색어가 포함되면 표시합니다. 컨텍스트 별칭도 화면에 표시된 경우 검색합니다. 기본 순서를 유지하고 긴 목록은 본문에서 스크롤합니다. `Name (target)`에서 괄호와 대상 주소에 보조 색상을 적용합니다. Name을 비워 둔 항목은 `(target)`으로 표시합니다. Context 열에는 실제 이름을, 메뉴의 대상에는 URL에 사용하는 컨텍스트 라벨을 사용합니다.
- 클릭하거나 키보드로 고른 행은 클립보드에 `http://` URL을 씁니다. 예를 들어 `http://api.default.prod.kuri.localhost`, `http://web.api.default.prod.kuri.localhost:8081`입니다. 쓰기에 성공한 행에서만 `Copied`를 1초간 표시한 뒤 원래 제목으로 복원합니다. 검색 결과가 바뀌거나 다른 행을 다시 복사해도 피드백은 각 항목 ID에 연결됩니다. 검색 필드의 편집 키와 한글 입력이 메뉴 단축키에 가로채이지 않게 합니다.

## 검증

각 단계의 지정 테스트를 먼저 작성하고 기대한 이유로 실패하는지 확인합니다. 해당 동작을 구현한 뒤 같은 테스트와 관련 패키지를 다시 실행합니다.

| 테스트 | 확인할 결과 |
| --- | --- |
| `TestBookmarkStoreOrderAndConflicts` / `TestExportRefusesBookmarksPath` | 파일이 없으면 빈 목록, 추가 순서 유지, 삭제와 재조회, 오래된 드래그 거부, 잘못된 파일과 저장 실패 시 원본 보존. 기존 설정 읽기와 Reset, Import, Export에 걸친 북마크 분리 및 내보내기 파일 경로 보호 검증. |
| `TestAddBookmarkDuplicateTarget` | 같은 조합을 다른 Name이나 다른 kubeconfig 경로로 제출하면 kubeconfig 및 Kubernetes API 조회와 북마크 파일 쓰기가 0회이며 기존 ID, Name, 순서를 보존함. 같은 Name으로 다른 대상을 추가할 수 있음. 빈 Port Name끼리 중복을 무시하고 명시한 Port Name은 별도 대상으로 저장함. 같은 요청의 재시도와 동시 제출에서 해당 조합이 하나만 남음. |
